### 2. Shared holdout/evaluator

`src/gems/holdout.py` assigns whole 8-connected components (or supplied integer segment IDs) to spatially selected blocks, excludes held components from the visible catalogue everywhere, and removes a 3-pixel buffer. Scoring truth is restricted to held fault pixels in lidar-covered selected blocks; component connectivity is a proxy, not an authoritative segment inventory. `src/gems57/evaluate_holdout.py` pools additive terms before the physical-block bootstrap and checks same-block truth counts across arms. The H66 runner has not produced a new result with these tools. The existing historical receipt is not relabeled as if it had been rerun.

### 3. Shared uniqueness gates

`src/gems57/uniqueness.py` now exposes distinct `surface` and `emitted` phases in the canonical shared module. Both phases check absolute Spearman rank correlation and exact decoded-pixel/hash identity; the 3-pixel dot-overlap threshold applies only to the final emitted-dot phase. This avoids treating all positive pixels of a dense continuous score surface as if each were a submitted dot. Missing, errored, or incomplete registry entries remain fail-closed. `src/gems57/gates.py` now forwards the phase to that shared implementation. `scripts/lane_check.py` reports absolute Spearman rather than Pearson and retains exact pixel and emitted-dot checks.

The historical post-placement screen remains only 62 of a recorded 655-raster corpus. Its prior sampled max absolute rank correlation (0.0196) and 3-pixel overlap (0.5099) are preserved as historical partial measurements; they are not a complete pass. No new surface/dot registry scan was run. `registry/template_provenance.json` now accurately records 21/23 files byte-identical to the historical external template snapshot; `uniqueness.py` and `gates.py` are deliberate shared-source changes in this branch. No upstream template merge is claimed.
