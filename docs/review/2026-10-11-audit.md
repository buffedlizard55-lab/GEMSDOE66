## Protocol and promotion gates

A future experiment must remain within the user's three-experiment / two-hour cap and use the shared tools rather than a local fork. The required protocol is:

1. Withhold whole authoritative fault segments, not short raster chunks, from spatial blocks; buffer each withheld segment. If authoritative segment IDs are not available, any connected-component proxy must be clearly disclosed and reviewed before it can support promotion.
2. Derive every catalogue-based feature only from visible faults. Mask visible fault pixels exactly from scoring. No hidden label may influence masks, candidate eligibility, thresholds, or placement.
3. Restrict both truth and scoring to LiDAR-covered holdout blocks. Test every proposed feature alone for leakage; AUC greater than 0.90 is a stop until disproven. Test the lead against the same frozen holdout baseline and report whether a gain persists away from prespecified range fronts.
4. Pool the official distance-weighted Tversky terms with α=0.2, β=0.8 and a 300 m triangular kernel. Every research score must be labeled `HOLDOUT-DTI` and carry the exact evaluator version, withheld-positive count, and 95% spatial-block confidence interval. No valid measurement exists now.
5. Hash and compare both the continuous pre-placement surface and the final dots with the complete registry. Correlation above 0.90 or more than 70% of candidate dots within 3 pixels of a registry raster is a duplicate/lane-drift stop. An incomplete registry is `BLOCKED`, never `PASS`.
6. Generate a candidate only after the lead beats the current valid holdout best under the same protocol. A submission slot is not a test instrument.
7. Before any download, validate a normalized single-band float32 GeoTIFF in EPSG:32611 against the exact official grid and footprint, with values in [0,1] inside and NaN outside. Keep the SHA-256, pixel checks, validator report, provenance, run card, reviewer sign-offs, unique submission name, and note (at most 140 characters).
