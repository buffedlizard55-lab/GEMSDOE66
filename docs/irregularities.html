IR-02-HOLDOUT-LEAKAGE · critical

Legacy emission eligibility uses distance to the full catalogue before holdout scoring

DISQUALIFIES LEGACY H66 HOLDOUT CLAIM

scripts/run_h66.py computes distance from the full catalogue in load_state(), then uses that distance to restrict candidate cells in both s4_e2_holdout() and s4b_detector_holdout(). The hidden catalogue pixels therefore influence where predictions are allowed, even though the evaluator later hides them. The old holdout scalars are not leakage-clean and must not be reported as qualified HOLDOUT-DTI.

Sources: S02

IR-03-HOLDOUT-DESIGN · critical

Legacy holdout is not the required buffered whole-geologic-segment, LiDAR-only instrument

BLOCKED — legacy H66 entrypoint disabled; shared protocol integration still required

The legacy gems57 holdout builder chunks raster branches into at-most-12-pixel pieces and erodes quadrant boundaries; it does not guarantee whole authoritative geologic segments are withheld with a buffer. The shared gems.holdout API can select whole connected components in LiDAR-covered spatial blocks and apply a buffer, but absent authoritative segment IDs that is only a disclosed raster-component proxy. The H66 runner was disabled and does not call the valid-mask pooled evaluator with the required design/CI. Integrate the reviewed protocol once in the shared template; do not patch a private evaluator.

Sources: S02, S04

IR-04-FEATURE-NAMING · high

Several H66 proxy fields were described as method-faithful Scarplet outputs

CORRECTED IN DOCUMENTATION; LEGACY FEATURES NOT QUALIFIED

In src/gems66/channels66.py, mean/max of two aggregate slope-excess bands is named a scarp-pixel fraction; the robust block z-score of an amplitude proxy is named template SNR; cross-face gradient divided by mean adjacent gradients is named morphologic relative age; and step_max multiplied by a fixed scale is named height. These are proxy constructions, not the published Scarplet template outputs. The owner-supplied 2 m stack/sidecar is not in the current checkout or organizer-authenticated. No current candidate may rely on those names as physical measurements.

IR-66-BASE-01 · high

The H66-2 stratum audit's first run used an index-ordered 'random' control

FIXED 2026-10-11 — superseded numbers recorded

scripts/h66b_strata.py drew its per-stratum random baseline with pick(np.ones(...)); argsort on a constant field returns cells in raster order, i.e. the top-left corner of the stratum, not a random sample. Every x-N-random ratio from that run was inflated roughly tenfold: the advertised x16 upland advantage of the H66-2 field is x1.20 against a uniform in-stratum baseline, and the incumbent's upland dots are x0.75, not x10. The corrected run replaces evidence/h66b_e2_strata.json; evidence/h66b_verdict.json carries the corrected ratios with the seed and the draw count.
