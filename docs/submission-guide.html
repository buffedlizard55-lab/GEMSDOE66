How to submit

Procedural guidance. The live submission form was not inspected because it requires an account login that this environment does not have.

Download: yes, for audit. Weekly slot: no.The file is format-validated (single-band float32, EPSG:32611, exact grid, all values finite in [0,1], no NaN anywhere — which is what fixes the earlier portal rejection "Predicted values must be in range [0, 1]"), it is unique against the scanned registry, and it passed the lane's channel gate; its headline mechanism measured negative, so it is not promoted. 2. Required scientific gate before writing a candidate

  1. Use the shared cached lidar stack, existing mask, segment-aware spatial holdout, and pooled DTI evaluator. Those inputs and the end-to-end evaluator are not currently in this checkout; do not replace them with a private implementation.
  2. Derive catalogue features from visible faults only and mask visible fault pixels exactly. Score only held-out lidar-covered spatial blocks; report range-front and non-range-front results.
  3. Run each feature alone as a leakage canary. AUC >0.90 is leakage until disproven.
  4. Compare the continuous surface to every registry raster before placement; compare final emitted dots to every registry raster after placement. Pearson correlation >0.90 or >70% of dots within 3 px means duplicate/stop. An absent registry is not a pass.
  5. Record `HOLDOUT-DTI` only with evaluator version, withheld-positive count, and 95% CI. No score or projection is inferred from the public leaderboard.

3. Local format checks (only after the science gate)

python scripts/verify_competition_data.py
python -m gems.validate_submission outputs/candidate.tif     --reference data/labels.tif --features data/training_features.tif
python scripts/lane_check.py --stage surface candidate_surface.tif registry_a.tif registry_b.tif
python scripts/lane_check.py --stage emitted candidate.tif registry_a.tif registry_b.tif

The data checker does not download files. The validator's exit code 0 is a format pass only; a skipped check is not a pass. The lane tool requires the complete registry and aligned rasters. A successful format check alone never clears the download gate.

4. Manual upload—only after a future clearance

  1. Confirm the run card says the candidate beat the frozen holdout best and all leakage, uniqueness, and format gates passed.
  2. Use the shared `submission_writer.py` to write a unique name and note of at most 140 characters. Record the exact file SHA-256 and validator output.
  3. Open the official submission form while signed in, check the live field labels and upload limits, then submit manually only if separately selected within the weekly cap.
  4. Record an organizer score only from the submission receipt and tie that receipt to the exact raster hash; label it `ORGANIZER-CONFIRMED`.

5. Do not

  • Do not upload or provide a file while the run card is negative.
  • Do not copy a raster from another team or publicly mirror competition data.
  • Do not scrape, monitor, or reproduce leaderboard values; use the official live page directly.
  • Do not report projections as scores or spend a slot without a holdout win.
