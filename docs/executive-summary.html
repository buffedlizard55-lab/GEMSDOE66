How to make a GEMS Prize submission

This page explains the file and form workflow. It does not imply that a current candidate is ready.

Current clearance

⛔ NO DOWNLOAD · DO NOT SUBMIT

There is no candidate TIF, submission name, or note in this repository. The scientific holdout, uniqueness comparison, and byte-level format validation are all unrun. The download button will only be enabled after those gates pass and the run card is updated.

File requirements

The official competition problem page requires a single-layer, single-band float32 GeoTIFF in the training data's projected CRS (EPSG:32611), at 100 m resolution, with the same bounds/grid and null or NaN outside the study bounds. Prediction values must be in [0,1], with higher values indicating greater confidence.

The run protocol for this project is stricter about verification: values must be in range within the footprint, NaN may occur only outside the footprint, and CRS, shape, transform, and bounds must match the template exactly. The file must be re-opened from disk and checked by the shared validator; none of those checks has run because the file and template are absent.

The form text quoted in the project brief accepts a single .tif or a .zip containing one GeoTIFF. The public format page explicitly documents a GeoTIFF. Use a ZIP only if the currently displayed competition form still accepts it; this project currently provides neither format. The quoted form shows a file selector and an optional Note, but does not establish a separate Name field. A unique filename is the project's artifact identifier; do not assume a portal field that is not shown.

Submission steps after a candidate is promoted

  1. Read the clearance first. On the project home page, verify that the specific file says both “download allowed” and “submit allowed.” A local format pass alone is not promotion. Current state: neither is allowed.
  2. Download only the promoted artifact. The site will show its unique filename, SHA-256, pixel-agreement/registry result, holdout evidence class, and validator receipt. Never upload a sibling project's raster or a file marked audit-only.
  3. Open the official competition page and submission form. Sign in to the account that is registered for the competition. This repository cannot access that account and will not store account credentials.
  4. Select the file. Use the promoted single-band GeoTIFF (or a single-TIFF ZIP only if the current form accepts it). Confirm the portal is selecting the same filename and byte hash that the project run card records.
  5. Enter the submission note. Paste only the short, artifact-specific note displayed next to that promoted file. Keep it within the project's 140-character note limit. Do not use an example or template note as a claim that a gate passed.
  6. Submit and retain the receipt. After the form returns a result, record the organizer's receipt and score against the exact filename and SHA-256. Label that result ORGANIZER-CONFIRMED only when copied from the official submission receipt.
  7. Leave final selection separate. Feedback submissions and weekly limits are controlled by the official competition rules. Do not upload automatically; choosing the one final entry is a separate, accountable decision.
